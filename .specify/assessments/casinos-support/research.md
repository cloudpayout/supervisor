# Idea Research: Casino support on start

- **Slug**: casinos-support
- **Created**: 2026-11-15
- **Evidence confidence (overall)**: medium

## Users & Demand

- One stated request, recorded in the intake note: Oscar Cedano wants `start` to load a session cookie (or cookies) and open a casino's main page. The attached sample names one casino, `Onewin`, page `https://1win.com/`, cookie name `session-id`, and states that some casinos need more than one cookie. The sample file had no cookie values. Later notes in the same intake say the runtime payload is JSON, originally either an inline string or a file path, that `onewin.com` will be supported, that cookies are set before the page opens, and that this slice stops at an authenticated main page. Later sentences in this note and in `problem.md` are his statements about the file path, the cookie fields, profile deletion, and permission to automate. They are not an observed session. — [source: `.specify/assessments/casinos-support/intake.md`; `.specify/assessments/casinos-support/problem.md`; Gaps & Open Questions below] (confidence: high)
- No other demand signal was found in this repository: no issue archive, interview notes, usage metrics, or earlier assessment about casino sessions. The want is stated once. It is not observed behavior from an existing session. — [source: repository search of `.specify/` and `specs/`] (confidence: high for absence in this repo; low that this is the only person who wants it)
- The README states the product purpose as the CLI that runs automations on casino games such as Aviator, Spaceman, and Dino, by driving chromedp. That is a stated product goal, not a count of operators or sessions. — [source: `README.md`] (confidence: high)

## Prior Art

- Feature 001 limits `start` to a blank page and puts casino, game, and automation selection out of scope. It says authentication, credentials, and named game or casino automation are future features. "Blank page" means a document such as `about:blank` with no casino or game URL loaded. The plan's constitution check records principle V as passing only because this slice starts no casino or game, and says a future spec extends it. — [source: `specs/001-supervisor-cli/spec.md` FR-010 and Assumptions; `specs/001-supervisor-cli/plan.md`] (confidence: high)
- The shipped `start` command takes no casino argument. Its only flags are mutually exclusive `--headed` and `--headless`. Help text says it starts one chromedp instance on `about:blank`. The worker navigates to `about:blank` and nothing else. The worker process is spawned as `worker run --id <id>` plus optional `--headless`. — [source: `internal/cli/start.go`, `internal/worker/run.go`, `specs/001-supervisor-cli/contracts/cli.md`] (confidence: high)
- The on-disk instance record has no casino, URL, or cookie fields. The feature 001 data model says the registry holds no secrets and treats credentials as a future runtime-only concern. — [source: `internal/registry/types.go`, `specs/001-supervisor-cli/data-model.md`] (confidence: high)
- Isolation was chosen so concurrent instances do not share cookies or storage: one Chrome user-data directory per instance, under `$XDG_DATA_HOME/supervisor/profiles/<id>/` (or `~/.local/share` when `XDG_DATA_HOME` is unset). — [source: `specs/001-supervisor-cli/research.md` decision 4; `specs/001-supervisor-cli/spec.md` Assumptions; `internal/registry/paths.go`] (confidence: high)
- No casino name, `1win`, `onewin`, or cookie-setting call exists in product or test Go code. Feature 001's testing decision is headless or mocked Chrome and no live casino. Later specs keep live-casino checks out of the default run. No `//go:build external` test exists. — [source: `internal/`, `tests/`; `specs/001-supervisor-cli/research.md` decision 9; `specs/001-supervisor-cli/quickstart.md`; `specs/003-record-test-results/research.md`] (confidence: high)
- The pinned browser stack can set cookies. `go.mod` requires `github.com/chromedp/chromedp` v0.23.0 and `github.com/chromedp/cdproto` v0.159.0. In that cdproto, `Network.setCookie` takes name and value plus optional URL, domain, path, secure, HTTP-only, SameSite, expiry, priority, source scheme, source port, and partition key. The comment on `URL` says it can affect the default domain, path, source port, and source scheme of the created cookie. `Network.setCookies` takes a list. The Go result type of `SetCookie` is empty, so this client does not surface a success flag. The same package lists reasons a cookie may not be stored, including `SecureOnly`, several `SameSite*` reasons, `InvalidDomain`, `InvalidPrefix`, `SchemeNotSupported`, and `NameValuePairExceedsMaxSize`. — [source: `go.mod`; module cache `github.com/chromedp/cdproto@v0.159.0/network/network.go` and `types.go`] (confidence: high)
- chromedp's public cookie example sets cookies, then navigates. It tells the reader it starts a local server and needs no internet. For each name/value pair it calls `network.SetCookie` with an expiry, `Domain: "localhost"`, and `HTTPOnly: true`, and only then calls `chromedp.Navigate`. It does not set a cookie from name and value alone, and it does not open a public site. `cdp.Call` and `chromedp.Func`, which that example uses, exist in the versions this module pins. Whether that example file builds unchanged against those versions was not compiled here. — [source: `https://github.com/chromedp/examples/blob/main/cookie/main.go`, pinned fetch; `github.com/chromedp/cdproto@v0.159.0/cdp/types.go`; `github.com/chromedp/chromedp@v0.23.0/action.go`] (confidence: high for the example text and for the presence of those APIs; low that the example compiles here unmodified)

## Data & Constraints

- Credentials and session cookies must be supplied at runtime and must not be committed. Browser control must use chromedp. The operator surface is the CLI. — [source: `.specify/memory/constitution.md` Principles II, Technical Constraints] (confidence: high)
- Constitution 1.1.0, Principle V, says Supervisor starts automations only for casinos and games it explicitly supports, and that every casino has games that can be run. A casino or game identifier must be one or more lowercase ASCII letters (`a-z`). Digits, punctuation, and uppercase letters must not appear. A host or URL must not be used as an identifier. The constitution's own example is that `onewin` is an identifier and `1win.com` is a URL. `Onewin` and `1win.com` fall outside that alphabet. A review must block a change that violates a MUST, and the principle must not be reinterpreted to fit the change. — [source: `.specify/memory/constitution.md` version 1.1.0, Principle V and Governance] (confidence: high)
- Automated tests must cover start, status, and stop, and the session lifecycle those commands control, before that behavior is complete. Default tests must run without a live casino site. A check that drives a real game must be marked external and must not gate the default run. The tests in this repository cover a blank page. None sets a casino cookie or opens a casino URL. v1 operator support is Linux and WSL2. — [source: `.specify/memory/constitution.md` Delivery Workflow; `specs/001-supervisor-cli/spec.md` FR-014; `specs/001-supervisor-cli/quickstart.md`] (confidence: high)
- The default checks job installs Go from `go.mod` and Chrome, then runs `go test -json ./...`. It does not install Python. A stakeholder statement now says that job's check for this behavior starts a local FastAPI server. That server is a new dependency of the job. — [source: `.github/workflows/default-checks.yml`; Gaps & Open Questions below] (confidence: high)
- The intake's first runtime model is a map of cookie name to value and omits domain, path, Secure, HTTP-only, SameSite, expiry, and partition key. A later stakeholder statement says the file must carry those fields. The CSV column is only the cookie's name, and no file containing a real value was provided. The chromedp example and the `SetCookie` parameter list both treat domain, HTTP-only, and expiry as part of setting a cookie. — [source: intake note; Gaps & Open Questions below; cdproto `SetCookieParams`; chromedp cookie example] (confidence: high)
- The same intake uses the identifier strings `Onewin`, `onewin`, and `1win.com`. Constitution 1.1.0 admits only `onewin` of those three as an identifier. A stakeholder statement says the main-page URL lives with the casino `onewin` rather than being typed on each start. — [source: `.specify/assessments/casinos-support/intake.md`; `.specify/memory/constitution.md` version 1.1.0; Gaps & Open Questions below] (confidence: high)
- The pasted JSON sample in the intake is not valid JSON: the second cookie key is missing its closing quote (`"cookie-2:`). No real cookie value was stored. — [source: intake note] (confidence: high)
- A secret placed on a process command line is readable on this platform. The product already reads other processes' command lines: the worker finds Chrome by scanning `Cmdline()`, and stop kills by profile path the same way. gopsutil implements that read as `/proc/(pid)/cmdline`. `start` today does not put secrets in that argument list. The stakeholder statement keeps it that way: `start` is given a file path, reads the JSON from that file, and neither `start` nor the worker receives the JSON document as an argument. Cookie values must also stay out of worker logs and the instance registry. The registry data model already forbids secrets. Overwriting `/proc/<pid>/cmdline` after startup was considered and set aside, because the original arguments stay visible until the overwrite and the shell can keep the typed command. — [source: `internal/worker/run.go`, `internal/proc/proc.go`, `internal/cli/start.go`; `github.com/shirou/gopsutil/v4@v4.26.10/process/process_linux.go`; `specs/001-supervisor-cli/data-model.md`; Gaps & Open Questions below] (confidence: high)
- A successful stop removes the registry row and kills the browser. It does not delete the profile directory. `RemoveProfile` runs on a failed start only. A cookie written into that Chrome profile would remain on disk under the data directory after the run ends. Profile directories are created with mode `0755`; the mode of files Chrome writes inside them was not checked. A stakeholder statement says the profile directory is deleted when the browser instance ends. The code does not do that today. — [source: `internal/cli/stop.go`, `internal/cli/start.go`, `internal/browser/chromedp.go`; Gaps & Open Questions below] (confidence: high for the current code and for the statement; the mode of Chrome's cookie files is unverified)
- `https://1win.com/` was not fetched. The host is not on the research allowlist, and this session did not get an explicit yes to fetch it. Nothing in the fetched sources shows that a cookie named `session-id` authenticates that site, which extra cookies it needs, or which cookie flags it requires. — [source: intake URL `https://1win.com/`; fetch skipped] (confidence: high that the site was not checked; the cookie contract is unverified)
- The DevTools protocol file `pdl/domains/Network.pdl` on `ChromeDevTools/devtools-protocol` `main` returned HTTP 404, so the protocol's own "url or domain required" rule was not read from that path. The requirement is not stated in the Go struct comments beyond the note that `URL` affects default domain, path, and scheme. — [source: pinned fetch of that URL; cdproto `SetCookieParams` comment] (confidence: high for the 404 and for the comment; the protocol rule itself is unverified)

## Evidence Against the Idea

- Demand evidence is a single intake statement and a one-row spreadsheet with a cookie name and no cookie value. There is no ticket volume, session log, or observed login that shows a cookie file produces an authenticated `1win.com` page. — [source: intake note] (confidence: high)
- The published chromedp example sets domain, HTTP-only, and expiry before navigation, on localhost. cdproto lists `InvalidDomain`, `SecureOnly`, and several SameSite reasons among the ways a set can be refused. A stakeholder statement now names those fields. No file with a real value was provided, and the live site was not checked. A later statement refuses to store a cookie value or a live session in this assessment. The local FastAPI check is the recorded proof. It does not show that `1win.com` accepted a cookie. — [source: intake note; Gaps & Open Questions below; `.specify/memory/constitution.md` Technical Constraints; cdproto `SetCookieParams` and `SetCookieBlockedReason`; chromedp cookie example] (confidence: high for the refusal and the missing observation; the 1win outcome is unverified)
- The default test run must stay off a live casino, and start, status, and stop must still be tested before the behavior is complete. A stakeholder statement names the check: a local FastAPI server that shows a balance only when the expected cookie is present. That check can show the cookie was sent to the local host. It cannot show that `1win.com` accepted one. The default job does not install Python today, so the check adds that dependency. A separate stakeholder statement names the live-page signal as the CSS selector `.adaptive-balance_number-GRGZd`. — [source: `.specify/memory/constitution.md` Delivery Workflow; `.github/workflows/default-checks.yml`; Gaps & Open Questions below] (confidence: high)
- Putting the JSON document on `start`'s command line would place session secrets where this program already reads command lines, in `/proc/(pid)/cmdline`. That form is ruled out by a stakeholder statement: the argument is a file path. Worker logs already capture the worker's stdout and stderr, so a cookie value printed there would still land on disk. — [source: gopsutil `process_linux.go`; `internal/cli/start.go`; Gaps & Open Questions below] (confidence: high)
- Stop leaves the Chrome profile on disk. A stakeholder statement says to delete it with the browser instance. The current code does not, and no check showed that the directory can be removed while Chrome is still writing it. — [source: `internal/cli/stop.go`; Gaps & Open Questions below] (confidence: high for the leftover directory; deletion timing is unverified)
- The stated product goal is game automation. Principle V requires explicitly supported casinos and games, and says every casino has games. A stakeholder statement names `aviator` and no other game. `problem.md` and `concept.md` still place Aviator, Spaceman, and Dino outside this slice. Feature 001 treated principle V as satisfied by starting neither a casino nor a game. — [source: `README.md`; `.specify/memory/constitution.md` version 1.1.0 Principle V; `specs/001-supervisor-cli/plan.md`; `.specify/assessments/casinos-support/problem.md`; `.specify/assessments/casinos-support/concept.md`; Gaps & Open Questions below] (confidence: high)
- Terms, age gates, and account rules for `1win.com` were not read. A stakeholder statement says automated sessions on this casino are allowed. That statement is the record of permission. It is not a fetched terms page. — [source: fetch skipped for host `1win.com`; Gaps & Open Questions below] (confidence: high that the page was not read; the statement is high confidence as a statement)

## Gaps & Open Questions

- Stakeholder statement, not an observation: the cookie file carries name, value, domain, path, expires, maxAge, secure, httpOnly, sameSite, and partitioned. No file containing a real value was provided.
- Stakeholder statement, not an observation: `start` receives a path to that file. The JSON document is not a process argument. Cookie values must not appear in `/proc/<pid>/cmdline`, worker logs, or the instance registry.
- Stakeholder statement, not an observation: the main-page URL lives with the casino `onewin`, and the profile directory is deleted when the browser instance ends. The current `stop` path still leaves the profile on disk.
- Stakeholder statement, not an observation: automated sessions on this casino are allowed. The site's terms were not read.
- Stakeholder statement, not an observation: on the live `onewin` page, an active session shows a balance, confirmed by the CSS selector `.adaptive-balance_number-GRGZd`.
- Stakeholder statement, not an observation: the ordinary test starts a local FastAPI server on `127.0.0.1`. The server reads one cookie and returns a page with a balance only when that cookie is present. The cookie in the test file is for that local host. The check runs `start` against that page, then `status` and `stop`. The live casino is not opened. The default checks job must install Python and FastAPI. The earlier statement "no test will be created" is withdrawn.
- Stakeholder statement, not an observation: the game name `aviator`. `problem.md` and `concept.md` still leave Aviator out of this slice.
- Resolved, stakeholder refusal: no cookie value will be stored, and no live `1win.com` session will be recorded in this assessment. The constitution forbids committing session cookies. The proof recorded here is the local FastAPI check. On a real run, the operator looks for the balance themselves. The selector `.adaptive-balance_number-GRGZd` stays their stated signal. It was not observed in this research.
- Resolved, stakeholder refusal: only `aviator` game will be used in this assessment. More implementations and how the game works will be defined in a later assesment, not this one.
